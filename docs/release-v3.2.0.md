# v3.2.0 — 记忆不再丢，定时任务能改，安全链收口

这一版几乎没有新功能，主要在补「用起来会发现不对劲」的地方：
聊久了忘了最初要干什么、摘要失败把内容吃掉、定时任务想改一句话得删了重建、
群里有人发广告、以及两条真实存在的越权路径。

升级要做的事只有一条：**确认 `.env` 里配了 `ADMIN_OPENIDS`**（见文末）。

---

## 记忆：从「能记」到「不丢」

三处结构性改动：

**第一轮锚点** —— `takeOverflow` 以前从最旧的开始丢，聊到后面它只记得最近的闲聊，最初那句需求被冲掉了。现在头部固定留一轮问答，只有之后的内容参与溢出。

**摘要失败回滚** —— 原来溢出内容已经从短期记忆移出，摘要又没写成，那段对话就永久消失。现在失败会把内容塞回原位、下一轮重试，连续失败 3 次才放弃。摘要为空也算失败（原来静默跳过，同样丢内容）。

**摘要挪到当前消息前** —— 从系统提示词里拿出来，包成 `<system-reminder>` 贴在用户这句话前面。系统提示词在最前面，模型对它的利用率不如紧邻提问的位置。

配套的四件事：

- **压缩前主动判断**：发请求之前先估一次，超过预算 85% 就先压再发，不用等接口回 `context length` 错误白等十几秒
- **上下文缺口提示**：压过的会话会插一条「中间省略约 N 轮、M tokens，没原文可查，需要细节就重新问」。以前它不知道自己少看了东西，会把摘要里的旧结论当刚说过的
- **群聊历史带说话人**：所有人共用一个会话，不记名字就分不清那句是谁说的
- **溢出原文归档**：`data/memory-archive/`，只写不读，摘要写歪时能人工核对，保留最近 200 个文件

摘要本身也从一段流水账改成【已定】【未定】【下一步】三段，上限提到 700 字 —— 多次压缩之后最容易出的错是把「还在讨论」写成「已经定了」。

## 定时任务：能改，能诊断

**新增 `update_schedule`** —— 改时间、改内容、暂停/恢复，就地改，任务 id 不变。以前只能删了重建，id 一变之前记住的就失效了。

**调度器可诊断** —— `/diag` 会打印：是否在运行、上次检查几秒前、pid、进程运行时长、每个任务的下次触发时间和上次结果。之前「到点了没触发」只能靠猜，现在一眼能分清是没启动、卡住了、cron 解析失败、还是任务被停用。

**两个真 bug**：

- `initScheduler` 排在一整个大 try 块中间，前面任何一步出问题它就不启动。现在提到网关连接之前，单独兜错
- 定时任务没把 `sessionKey` 传给 agent，里面一直是默认的 `worker`，导致所有读群记录的工具报「只能在群里用」

**漏跑会补**：原来只在启动后 20 秒补一次，错过那一分钟就得等下一小时。现在每 20 秒的检查都会补，同一时间点只补一次。

**权限收紧**：删任务、改任务都要创建者本人或管理员；旧任务没有创建者记录，只有管理员能动；任务文件损坏时先备份再按空启动，不再静默清空。

## 消息

**按钮一行一个** —— 平台是按「这一行几个按钮」平分宽度的：5 个挤一行显示成 `1. ...`，3 个一行显示成 `1. 再来……`，独占一行才完整。

**选择题正文也列选项** —— 之前只有题干，选项全在按钮上，按钮没渲染出来就不知道能选什么。

**配图嵌进正文** —— 官方 markdown 支持内联图片，公网地址平台会自己转存；本地图先上传成 `qqbot-media://` 引用。分段时不会把 `![图](地址)` 切开。

**广告提醒** —— 群里出现「广告词 + 微信/电话/链接」或「扫码进群」这类拉人话术时，@ 对方软提醒一句，这条不再往下接。纯规则判定不调模型；同一个人 24 小时只提醒一次、同一个群一小时最多 3 次、管理员不提醒。

## 安全

| 问题 | 处理 |
|---|---|
| `recall_message` 能跨群撤回 | 只能动当前会话、台账必须命中才发请求；跨群要管理员；工具本身收进高危 |
| `isAdmin` 的私聊 fallback 被用来判跨会话能力 | 新增 `isConfiguredAdmin()`（只认白名单），读别的群、看所有任务、撤别的群都换用它 |
| 自动 push 让模型改的代码直接进 main | 自动同步只推 `auto-backup` 备份分支，main 改由人工触发，备份习惯不变 |
| 审计只覆盖对话循环 | 下沉到 `client.js` 的 `callTool()`，定时任务、子 agent、自愈、命令全路径留痕 |
| 配图放行分支是 fail-open | 改成 fail-closed：只有明确 DNS 解析失败才保留，未知错误一律丢 |
| 出网错误靠文案匹配 | 改结构化错误码（`BLOCKED_ADDRESS` / `DNS_FAILED` / `BAD_REDIRECT` …） |
| 工具定义了但权限表没登记 | 补齐 `goal` / `notify_user` / `recall_message`，并加「工具定义 ↔ 权限表」一致性断言 |
| `isAdmin` 少传 scope 恒为 false | 修正调用点，少传参数时打 warn |

高危工具现在是 **18 个**（之前文档写 16、后来写 17，都漏了 `file_copy`）。加了一条测试同时校验 `.size` 和文档里的列举，以后不会再漂。

## 升级

### 先确认白名单

`recall_message` 收进高危之后，有个前提变了：

> **如果 `ADMIN_OPENIDS` 是空的，群里连管理员都用不了高危工具，而私聊里任何人都能用**（这是 `isAdmin` 的私聊 fallback，一直如此）。

所以升级前先看一眼 `.env`：

```bash
grep ADMIN_OPENIDS /etc/dafeiyu/env /qq/.env 2>/dev/null
```

为空的话先填上，不然撤回功能在群里会直接不可用。

### 部署

```bash
cd /qq && git pull --rebase origin main && pnpm install && pm2 restart dafeiyu && pm2 save
```

重启后确认日志里是：

```
[启动] 版本 v3.2.0｜xxxxxxx｜进程启动于 2026/11/7 ...
[定时] 已加载 N 个任务（启用 M 个），每 20 秒检查一次
```

### 会感觉到的变化

- 群友不能再撤回机器人发的消息（只有白名单里的人能）
- 自动同步推到 `auto-backup` 分支，`git branch -r` 能看到；要让改动进 `main`，说一句「提交并推送」
- 长会话不会再忘记最初的需求，被压缩的部分会明确告诉用户「中间省略了，需要细节重新问」
